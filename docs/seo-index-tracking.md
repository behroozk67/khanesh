# پیگیریِ ایندکس آزمایار — سنجشِ ۱۸ اکتبر ۲۰۲۶ (۱۴:۰۰ به وقت تهران)

> این سند «گام ۳ — پیگیری» است: به‌جای فشار دادنِ دوبارهٔ دکمهٔ Request Indexing،
> وضعیت را از منابعی می‌سنجیم که لاگین نمی‌خواهند (لاگِ خزشِ سرور + ایندکسِ عمومی)،
> و در انتها فقط ۴ عددِ مخصوصِ سرچ‌کنسول برای کاربر می‌ماند.

## ۱. خزشِ گوگل — شاهدِ قطعی از `nginx.access.log`

| تاریخ | درخواستِ Googlebot | Bingbot | Yandex/DuckDuck/Apple | فایل |
|---|---|---|---|---|
| ۱۵ اکتبر | ۱۸ | ۲۶ | ۲۲ | `access.log.3.gz` |
| ۱۶ اکتبر | **۲۵۵** | ۰ | ۱۵ | `access.log.2.gz` |
| ۱۷ اکتبر | ۸۱ | ۱۸ | ۰ | `access.log.1` |
| ۱۸ اکتبر (تا ۱۳:۱۶) | **۱۰۶** | ۴ | ۰ | `access.log` |

* **۳۳۳ آدرسِ یکتا** توسط Googlebot خزش شده (از ۳۰۴ آدرسِ sitemap + اَسِت‌ها/`favicon`/`robots.txt`)
  ⇒ پوششِ خزش عملاً کامل است.
* کدهای پاسخ در ۱۸ اکتبر: `200` ×۱۰۳ و `304` ×۳ — **هیچ ۴۰۴/۵۰۰/۴۰۳**.
* `sitemap.xml` سه بار خوانده شده: ۱۷ اکتبر ۱۶:۰۹ و ۲۰:۴۹ · ۱۸ اکتبر ۱۳:۰۵.
* آخرین خزش‌ها (۱۸ اکتبر): `/`، `/methodology`، `/test/cbc`، `/test/tsh`، `/test/vitd` (ساعت ۱۳:۱۰–۱۳:۱۶).
* پرخزش‌ترین مسیرها: `/robots.txt` (۱۹) و `/` (۱۲) — طبیعی است.

**تعریف این اعداد:** خزش ≠ ایندکس. گوگل صفحه را دیده و پاسخِ ۲۰۰ گرفته؛ اینکه در
نتیجهٔ جست‌وجو بیاید، تصمیمِ جداگانهٔ رتبه‌بندی است.

## ۲. ایندکسِ عمومیِ صفحه‌های کلیدی (سنجش با کوئریِ `site:`)

| آدرس | در ایندکس دیده شد؟ |
|---|---|
| `/test/cbc` | ✅ بله (نتیجهٔ عیناً همان آدرس) |
| `/test/vitd` | ✅ بله |
| `/test/ferritin` | ✅ بله |
| `/tests` (زیرصفحه‌ها: `wellness`, `infectious`, `cardiac`) | ✅ بله |
| `/methodology` (۱۸ اکتبر منتشر شد) | ❌ هنوز نه |
| `/test/hba1c` | ❌ هنوز نه |
| `/units-guide` | ❌ هنوز نه |

⚠️ دو محدودیتِ روش را در نظر بگیر:
1. کوئریِ مستقیمِ `site:` روی `google.com` از این شبکه با کپچا (`/sorry/index`) رد می‌شود —
   پس سنجش از نتایجِ موتورِ واسط انجام شده، نه از خودِ گوگل.
2. Bing با اسکرپینگ قابلِ اتکا نیست (خروجی نویزی)؛ تنها شاهدِ واقعیِ Bing، لاگِ سرور است:
   Bingbot در ۳ روزِ گذشته فعال بوده و IndexNow هم `200 — 304 آدرس` گرفته است.

**نتیجه:** صفحه‌های قدیمی‌تر در ایندکس هستند؛ صفحه‌های تازه (روش‌شناسی، HbA1c) برای
ایندکس‌شدن به همان «چند روز تا ۲ هفته» نیاز دارند — نه به درخواستِ دوباره.

## ۳. چهار عددی که فقط سرچ‌کنسول می‌دهد (کارِ کاربر، هر ۳–۷ روز)

| سنجه | مسیر در سرچ‌کنسول | مقدار (تاریخ: …) |
|---|---|---|
| تعداد صفحه‌های ایندکس‌شده | `Indexing → Pages` → کارتِ `Indexed` | — |
| صفحه‌های خزش‌شدهٔ ایندکس‌نشده | همان صفحه → `Why pages aren't indexed` | — |
| وضعیتِ یک آدرسِ خاص | `URL Inspection` → «URL is on Google» | — |
| کوئری‌های واقعیِ کاربران | `Performance → Queries` | — |

**راهِ خواندن:** در `Pages` روی ردیفِ `Crawled – currently not indexed` که کلیک کنی،
فهرستِ آدرس‌ها و **آخرین زمانِ خزش** می‌آید. اگر آنجا `Discovered – currently not indexed`
دیدید، یعنی گوگل هنوز وقتِ خزش نگذاشته (طبیعی برای دامنهٔ نو)؛ اگر
`Crawled – currently not indexed` بود، یعنی دیده و ارزشِ ایندکس ندانسته ⇒ راه‌حل
محتوا + لینکِ داخلی + بک‌لینک است، نه درخواستِ بیشتر.

## ۴. کارِ روزمرهٔ من (بدون لاگین)

```bash
# هر چند روز: پوششِ خزشِ گوگل و بینگ از لاگِ سرور
ssh -i ~/.ssh/YOUR_KEY root@<server-ip> \
  'zcat -f /var/log/nginx/access.log* | grep Googlebot | awk "{print \$7}" | sort -u | wc -l'

# بعد از هر انتشار: اعلام به ایندکس‌ها
cd khanesh && npm run indexnow      # انتظار: «200 — N آدرس»
```
