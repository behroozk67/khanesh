# قالبِ پروندهٔ استخراج

خروجیِ مهارتِ `clinical-knowledge-extraction` دقیقاً این ساختار را دارد. بخشی که
دادهٔ متناظر ندارد حذف نمی‌شود — با «— در متن نبود» می‌ماند، تا معلوم باشد نگاه شده.

---

```markdown
# استخراج: <نام سند> — <فصل/بخش>

**منبع:** <عنوان کامل، ویرایش، سال>
**دامنهٔ متن:** <صفحات/بخش‌هایی که واقعاً خوانده شد>
**تاریخ استخراج:** <YYYY-MM-DD>
**فهرست‌برداریِ موتور:** `engine-inventory.mjs` اجرا شد — <N> قاعده، <M> کلیدِ نمره‌دهی

---

## ۱. قوانینِ شرطی و آبشارهای تشخیصی

### R1 — `condition_name_pattern`  🆕
| فیلد | مقدار |
|---|---|
| شرط | `IF (FERRITIN < 30 ng/mL) AND (TSAT < 20 %) AND NOT (CRP > 5 mg/L)` |
| فاز | حاد / مزمن / اولیه / ثانویه / — |
| فوریت طبق متن | `this_week` — «…نقلِ قولِ متن…» |
| پاتوفیزیولوژی | <یک‌دو جمله> |
| باید گفته شود | <هستهٔ بالینی> |
| گامِ بعدی | <آزمایشِ تأییدی + بازهٔ زمانی> |
| استثنا / تبصره | <پاورقی‌ها، شرایطی که قاعده را باطل می‌کند> |
| منبع دقیق | <سند، جدول/شکل/صفحه> |
| چه چیزی را کامل می‌کند | (فقط برای ➕) شناسهٔ قاعدهٔ موجود |

**آبشار (اگر متن درخت تصمیم دارد):**
```
مقدار غیرطبیعی
├─ اگر PTH بالا  → R2
├─ اگر PTH پایین → R3
└─ اگر PTH نرمال → R4  ← «نامعین»، نه «طبیعی»
```

**فرمول‌ها:**
| نام | فرمول | واحد خروجی | پیش‌شرطِ اعتبار |
|---|---|---|---|
| شکاف آنیونی | `Na − (Cl + HCO3)` | mEq/L | <آنچه متن می‌گوید> |
```
