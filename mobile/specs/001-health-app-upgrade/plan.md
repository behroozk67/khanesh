# Implementation Plan: Azmayar App Upgrade

**Branch**: `001-health-app-upgrade` (work stays on `master`, uncommitted) | **Date**: 2026-11-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-health-app-upgrade/spec.md`

## Summary

Turn the single-screen prototype into a 4-tab app. The existing `api.ts` job flow is kept; around
it: camera/gallery/PDF intake, haptics + reanimated progress/reveal, a result screen rendering the
server's `_engine` (score, systems, phenoAge, tests) with SVG charts and a PDF export, an
on-device history store feeding the History tab, a vendored copy of the site's encyclopedia
content, and a local challenges/streak store with weekly local notifications.

## Technical Context

**Language/Version**: TypeScript 6 (strict), React 19.3, React Native 0.88

**Primary Dependencies**: Expo SDK 58, expo-router (JS tabs), react-native-reanimated (installed);
new via `npx expo install`: expo-haptics, expo-print, expo-sharing, expo-notifications,
react-native-svg, react-native-webview, @expo/vector-icons

**Storage**: AsyncStorage (installed) — history records, challenge enrolments

**Testing**: No runner (constitution). Pure logic in `src/lib/*.ts` gets an assert-based
self-check script run with `node --experimental-strip-types`; plus `npx expo lint`, `npx tsc --noEmit`,
and a web smoke run in Chrome.

**Target Platform**: Android + iOS via Expo Go / dev build; web for smoke tests

**Project Type**: mobile-app (client of the existing khanesh-server)

**Performance Goals**: 60 fps animations (reanimated, UI thread); result screen opens < 1 s
after the server result arrives

**Constraints**: Persian RTL only; offline-capable encyclopedia; no client-side clinical logic

**Scale/Scope**: 4 tabs + 2 pushed screens (result, test); ~70 encyclopedia tests; ≤50 stored analyses

## Constitution Check

| Principle | Check | Status |
|---|---|---|
| I. Backend owns clinical judgment | Score/band/systems/phenoAge read from `_engine`; history change = arithmetic difference with neutral wording; encyclopedia text vendored verbatim from khanesh source; challenges are generic habits | PASS |
| II. Persian-first RTL | Render `fa`/`name`; numbers+units wrapped in LRI/PDI isolates; PDF HTML `dir="rtl"` | PASS |
| III. Few screens | 4 tabs; result + test detail pushed | PASS |
| IV. Feedback on core loop | `feedback.ts` wraps haptics (no-op on failure); progress + reveal animated | PASS |
| V. Local-first data | history + challenges in AsyncStorage; only pages + age/sex sent | PASS |
| Platform constraints | all packages via `npx expo install`; `api.ts` remains the only network client (PDF renderer loads pdf.js from cdnjs inside a WebView — a static asset, not an API) | PASS (noted) |

Post-design re-check: PASS — see Complexity Tracking for the one judgment call.

## Complexity Tracking

| Item | Why needed | Simpler alternative rejected because |
|---|---|---|
| Vendored encyclopedia (`src/content/khanesh/`) | FR-010 demands identical content; ~12k lines of Persian | Hand-porting would drift and re-author clinical text (violates I) |
| WebView pdf.js renderer | Server only accepts images; RN has no built-in PDF rasteriser | Native PDF libs need a dev build and config plugins; uploading the PDF raw is unsupported by the server |
